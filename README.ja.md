# cc-shiori（栞）

[English](README.md)

並行して回している Claude Code のセッションに戻ったとき、**そのセッションの中だけ**から次の3つを示す栞です。

1. **どこまで来たか** — 目的・現状・次（完了・決定も）
2. **あなたの番か** — Claude があなたの回答・判断・作業を待っているか（`?2 ◇1 !1`）
3. **あの番号は何だったか** — 出てきたチケット（`ABC-123`）・PR（`owner/repo#12`）・タスク（`T-012`）などが、このセッションで何を指していたか（索引）

複数のセッションを並べて回していると、切り替えた先で「これは何をしていたセッションか」「今こっちの番なのか」「`t-0005` って何だっけ」が分からなくなります。セッションの側は覚えていても、人間は忘れます。栞はそれを入力欄の上の帯とサイドバーに出します。

栞は1冊の本（セッション）に1枚挟まるもので、ほかのセッションや作業ディレクトリは見ません。どのセッションへ行くかを決めるのはターミナル側（herdr などのサイドバー）の役目で、栞は行った先で「どこまで読んだか」を示します。

## 表示

**入力欄の上（帯）**: 1行目は行頭の記号と現状と「詳細」ボタン、2行目は目的。記号は現状が長くても切れません。帯の先頭には 🔖 が付きます。サイドバーを開いている間は、帯は「🔖 栞  ?2 回答 · !1 作業」のように状態だけを言葉つきで出します（中身はサイドバーにあるので）。

| 記号 | 意味 |
|---|---|
| `?2 ◇1 !1`（黄） | あなた待ちの件数を種類ごとに: `?` 回答してほしい質問・`◇` 判断（選択・承認）・`!` 手作業（URL を開く、ログイン、コマンドを打つ、画面を確かめる） |
| `●` | 作業中（あなた待ちが無いとき） |
| `✓` | 区切りがついた（次が無い） |
| `○` | 待機 |

あなた待ちとその種類は Haiku が判断します。ただし最終回答が「？」で終わったのに Haiku が何も挙げなかったときは、その一文を `?` として立てます（記号がモデルの判断だけに頼らないように）。

**サイドバー**（`/shiori` または「詳細」）:

| 項目 | 中身 |
|---|---|
| 目的 | セッション全体で何を達成しようとしているか |
| 現状 | 今どこまで来ているか |
| あなた待ち | Claude があなたの回答・判断・作業を待っていること（`?` `◇` `!` と種類つき） |
| 次 | 次にやること |
| 索引 | 出てきた番号と、それが何を指すか（最後に話題になった順）。ID・種類・中身を列で揃えて出す |
| 完了・決定 | 最新 6 件ずつ |

## インストール

```text
/plugin marketplace add mitaku/cc-shiori
/plugin install shiori@cc-shiori
/reload-plugins
```

Claude Code 2.1.289 で動作を確かめています。mod（関数フック）の API はまだ試験段階で、Claude Code の更新で動かなくなることがあります。

## 使い方

- 普段どおり会話すれば、本体のターンが終わるたびに栞が更新されます（ターンは待たせません）
- `/shiori` … サイドバーを開く
- `/shiori refresh` … 直近のターンから作り直す（前回の栞は引き継ぐ）
- `/shiori refresh --hard` … 前回の栞と索引を捨てて、直近のターンとそれまでの依頼から一から作り直す（索引に古い話が残り続けるとき）

言語は Claude Code の `language` 設定に従います（`Japanese` なら見出しも中身も日本語）。

### 索引のリンクと詳細

- 索引の ID は、URL が分かればリンクになります（クリックで開く）。GitHub の PR・Issue・コミット（`owner/repo#12`、`owner/repo@sha`）は設定なしで。リポジトリ名の無い `#12` やハッシュはリンクにしません（どのリポジトリかを cwd から推測すると、複数のリポジトリをまたぐセッションで間違った先へ飛ぶため）。
- それ以外（Backlog、Jira など）は、`/config` の **Index links**（`pluginConfigs` の `shiori.linkRules`）に `正規表現 => URL の型` を `;` 区切りで書きます。`{id}` は ID 全体、`{1}` `{2}` は正規表現のグループです。

  ```text
  [A-Z][A-Z0-9_]+-\d+ => https://example.backlog.jp/view/{id}
  ```

- リンクを開けない端末（ブラウザの無いコンテナ、ハイパーリンクを通さない多重化ソフトの中など）のために、ターミナルでは URL のある行に `⧉` が付きます（デスクトップではリンクで開けるので出しません）。押すと URL をクリップボードへコピーします（OSC 52 など、端末の `/copy` と同じ経路）。
- 索引の行にポインタを乗せると、その下に中身の全文・種類・URL・最後に出てきたターン、そして**最後に出てきた発言の一節**（誰の発言か付き）が開きます（ポインタが使える画面で）。
- ターミナルでは各行に `↥` が付き、その ID が最後に出てきた発言へ会話をスクロールします（デスクトップアプリはプラグインからの会話のスクロールを受け付けないので、そこでは一節の引用で代わりにしています）。

## 仕組み

- **栞はセッションの中で閉じています。** 材料はそのセッションの会話だけで、ほかのセッションや作業ディレクトリのファイル・git の状態は見ません。複数のセッションを見渡すのは、ターミナル側（herdr などのサイドバー）の役目です。
- 本体のターンが終わるたびに、**前回の栞と新しいターン**（依頼・最終回答・主なツール操作）だけを Haiku に渡して、栞を更新します。会話全体は送りません。ファイルの読み込みや検索の結果も送りません。
- 索引は「そのセッションが会話の中で理解している中身」です。モデルが書き落とした項目も消さず、新しく出てきたものや中身が変わったものほど上に来ます。
- 栞はセッションごとに mod のストア（`~/.claude/plugins/store/`）へ保存し、最新 200 件を残します。再開時は、最後のターンの栞があればそのまま出し、古ければ作り直します。`/clear` で新しく始めます。
- 非対話の実行（`claude -p`）やサブエージェントのターンでは動きません。

## 費用

本体のターンごとに Haiku を1回呼びます（セッションと同じアカウント・プロバイダ）。呼び出し回数はサイドバーの下に出ます。止めるときは `/plugin` で無効にしてください。

## 保存するもの

栞（目的・現状・決定・索引など）は、セッションごとに `~/.claude/plugins/store/` へ**平文で**保存します（最新 200 セッション分）。索引には、その ID が出てきた**会話の一節がそのまま**入ります。業務の会話で使うときは、その前提で使ってください。消すときは `/plugin` で無効にしたうえで、そのストアを削除します。

## 関連

[skanehira/claude-recap-plus](https://github.com/skanehira/claude-recap-plus) も、セッションの要約を入力欄の上に出す mod です。栞は別々に考えていたもので、似た発想の実装があることを途中で知りました。比べて、合うほうを使ってください。
